# 映读

YouTube 频道订阅与视频精读工作台。应用 id 和用户数据目录保持不变。

## 使用
1. 在 NewMax 侧栏打开「映读」。
2. 连接器已配置为当前 Windows 用户登录后静默启动，无需终端。本次已立即启动；异常离线时双击 `start-connector-silent.vbs` 手动恢复。原 `start-connector.cmd` 仅用于可见终端诊断与依赖修复。
3. 点击「订阅频道」，输入 `@handle`、频道主页或 UC 频道 ID。
4. 选择视频，在「视频文稿」阅读或检索字幕；时间戳打开对应原视频。
5. 点击「全文一次解析」，完整文稿一次提交、直接生成最终解析。模型容量不足时可手动选择「兼容分段」，旧分段进度可继续。再进入「阅读对话」追问；解析中的时间引用会定位到文稿。

也可直接「导入文稿」：SRT / VTT / TXT，最大 2 MB / 24 万字符。导入文稿可通过「移除」删除，删除需确认。字幕和笔记可导出。

## 更新与字幕
- 默认每 30 分钟检查，可在左下角设置中调整。
- 首次最多读取 20 条近期视频；每轮自动尝试最新 3 条新视频的字幕，其他视频可手动获取。
- 连接器运行时即使关闭阅读窗口也会同步；关闭连接器就停止。连接器不是 NewMax 自动运行的 backend。
- 订阅是本地资料管理，不会修改 YouTube 账号订阅。
- 没有字幕、网络受限、访问限制都会显示真实错误，可手动重试或导入。不读取浏览器 Cookies，不绕过登录限制。常规订阅仅抓取字幕；图文取图时才按需读取视频媒体，不归档整段视频。
- 取消订阅只停止更新，保留已获取的视频、字幕、解析与对话。

## 图文排版与视频截图
1. 进入视频的「图文排版」，编辑的是独立副本，原解析不变。
2. 在正文下方点击「从视频取图」，根据正文时间引用推荐最多5个位置。推荐不调用AI，也不会自动读取视频；没有时间引用时，可把光标放在正文中，点击「当前光标位置」并手动填写时间。
3. 调整时间（例如 `4:29`），点击「获取候选截图」。需要连接器在线且本机FFmpeg可用；会读取视频媒体，产生网络流量。受限视频或取帧失败会显示错误，不用封面冒充截图。
4. 预览画面，勾选后点击「插入所选」。图片放入推荐段落或记录的光标位置；正文中途变化时需重新推荐，防止错位。可在“已插入视频截图”中定位或移除。
5. 点击「保存排版」后截图和来源时间一起保存在本机。PNG/ZIP包含所选画面，图片纸面不显示时间引用。未插入的候选不会导出。

截图不发送给模型。一次最多5张，失败不自动重试；关闭编辑器不保证后台已取消。候选是临时结果，只有插入并保存后才属于排版草稿。请使用有权使用的画面，不绕过登录或访问限制。本地导入资料不支持自动取帧，可上传自己的配图。

## 自动启动与停止
- 启动项：当前用户 Startup 目录的 `Yingdu-Connector-app-f73ecc67.lnk`，直接启动本应用虚拟环境 `pythonw.exe`，不需要管理员权限、不依赖 NewMax 开窗。关机或未登录时不工作；不是云服务。
- 设置 → **停止后台更新**：优雅停止当前连接器，保留队列与全部资料；下次登录仍会启动。
- `disable-connector-autostart.cmd`：取消登录自启，不强行停止当前实例。永久停用时先取消自启，再在设置停止。
- `enable-connector-autostart.cmd`：重新配置登录自启并立即启动。
- 启动错误在独立数据目录 `connector/background.log`，日志轮转且不输出 token。若 Windows 禁用启动项，需要在系统启动应用管理中重新启用。
- 启动不自动安装依赖、不触发 AI；重复启动通过健康检查和两层实例锁保护。
- 本轮验收执行了相同快捷方式的启动链，没有为测试注销或重启你的电脑。

## AI 与隐私
- 使用 NewMax 当前默认模型，也可在设置中从实时模型列表选择。应用不保存模型密钥。
- 只有点击解析或发送问题才产生请求；云端模型会收到相应文稿，可能产生费用。
- 默认全文一次解析，不按字符数自动切段；输出采用自动预算，不再使用旧的 4000/8000 设置。也可在设置输入自定义正整数，应用不设置固定的小输出上限。自动不等于无限：服务默认、协议要求、上下文剩余空间与模型真实能力仍有效。
- 默认最长等待 15 分钟，可在设置调整；失败不自动重试/换模型/切段。仅确认正常结束才标为完成，截断/超时/未知结果保存为独立未完成草稿，旧解析与分段保留。
- 旧接口生成的笔记没有结束原因，显示“完整性未确认”，不会删改正文。
- 失败请求和手动重试均可能产生费用，不能承诺不计费。
- 阅读对话提供完整文稿、完整解析和所有已有对话，不再按固定字符数静默截取。超过实际容量时显示错误。
- 需要新版 NewMax 主进程与 preload 配套构建并重启；只刷新映读不足。应用通过模型目录的主进程能力声明检测兼容，旧宿主不会发送 AI 请求。
- 模型输出仍需与原文核验；不保证没有错误。关闭窗口不保证取消已提交的模型请求。

## 文件与验证
- `src/`：无构建依赖的前端，运行入口 `src/index.html`。
- `connector/`：仅监听本机回环的 Python + yt-dlp 连接器，详见其 README。
- `tests/core.test.mjs`：18 项字幕、输入、过滤、上下文与转义测试。
- `tests/ui-harness.html`：隔离 UI 测试页，只能用模拟 SDK，不连接真实 AI 或网络；不进入用户资料库。
- `ACCEPTANCE.md`：实际窗口验收与已知限制。

```bash
node --check src/app.js
node --test tests/core.test.mjs
./connector/.venv/Scripts/python.exe -m unittest connector.test_server -v
```

数据由 NewMax data/files API 和连接器保存在应用独立 app-data 目录。随机本地连接令牌不在源码中；不要共享数据目录中的 `connector/connection.json`。
